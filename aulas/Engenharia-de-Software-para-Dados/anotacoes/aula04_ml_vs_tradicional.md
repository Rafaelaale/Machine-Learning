# Aula 04 - Sistemas de ML vs Software tradicional

## Objetivo da aula

Compreender a diferenca entre sistemas
tradicionais e sistemas de Machine Learning.

## 1. Sistema de Machine Learning

Segundo a aula, nao e somente o modelo.

Envolve um conjunto de etapas:

- Entendimento do problema e requisitos.
- Coleta e preparacao de dados.
- Engenharia de atributos.
- Treinamento.
- Hiperparametros.
- Experimentos.
- Testes e validacao.
- Versionamento.
- Monitoramento.
- Manutencao.

## 2. Software tradicional

Utiliza regras programadas.

Exemplo do curso: sistema de registro de ponto.

Entradas sao processadas segundo as regras
e funcionalidades implementadas.

## 3. Diferenca central

Software tradicional:
O comportamento e definido pelas regras.

Machine Learning:
O sistema aprende padroes a partir de dados
para realizar previsoes sobre novas entradas.

## 4. Dependencia de dados

Modelos de ML sao particularmente sensiveis
a mudancas de estrutura, distribuicao e
qualidade dos dados.

Exemplos:

- Colunas removidas.
- Alteracao de codigos de produtos.
- Mudanca nas caracteristicas dos clientes.
- Alteracao na distribuicao dos atributos.

Observacao complementar:
Softwares tradicionais tambem podem falhar
quando recebem dados invalidos ou incompativeis.

## 5. Engenharia de software para dados

A aula destaca:

- Codigo modular.
- Testes.
- Documentacao.
- Planejamento.
- Versionamento.
- Manutencao.
- Monitoramento.
- Responsabilidades claras.

## 6. Profissionais envolvidos

A aula menciona a colaboracao entre:

- Cientista de Dados.
- Engenheiro de Dados.
- Engenheiro de Machine Learning.

## 7. Laboratorio complementar

Comparamos dois sistemas com dados ficticios.

Sistema tradicional:
Classificacao baseada em regras fixas.

Sistema ML:
Classificador simples por centroides,
treinado a partir de exemplos rotulados.

Tambem implementamos:

- Separacao entre treino e teste.
- Validacao de colunas obrigatorias.
- Avaliacao de acuracia.
- Alerta didatico sobre mudanca na media.
- Testes automatizados.

Este laboratorio nao representa um sistema
real de previsao de abandono de clientes.

## 8. Principal aprendizado

Aplicar Engenharia de Software em ML permite
organizar, testar, documentar e manter
os componentes que formam todo o sistema,
e nao apenas o modelo.
